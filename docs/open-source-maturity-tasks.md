# 开源成熟化任务拆分

本文是 [`open-source-maturity-requirements.md`](open-source-maturity-requirements.md) 的执行清单。任务按依赖顺序排列；完成标准是合并条件，而不是建议。

## 里程碑与关键路径

```text
P0 可信发布基线 ──> P1 自动化质量门禁 ──> P2 开源协作契约
          └──────> P3 数据与研究可复现 ──> P4 安全/交易边界
                                             └──> v1.0 发布治理
```

## P0 — 可信发布基线（阻塞下一次正式发布）

| ID | 任务 | 依赖 | 完成标准 |
|---|---|---|---|
| P0-01 | 修复集成测试回归 | 无 | `uv run pytest tests/ -q` 全绿；测试不再因 `Settings`/策略参数为 `MagicMock` 而失败。 |
| P0-02 | 重建测试配置 fixture | P0-01 | 单元与集成测试使用真实 `Settings` 或受限的 typed fake；新增配置字段时测试会明确失败。 |
| P0-03 | 隔离网络测试 | P0-01 | 默认 pytest 禁止 socket/HTTP；数据源真实连通性移入 `smoke` 标记，且不作为 PR 必跑项。 |
| P0-04 | 修复 TLS 警告 | P0-03 | 测试及运行时没有未验证 HTTPS 请求；不通过 `verify=False` 或屏蔽警告规避。 |
| P0-05 | 对齐包元数据 | 无 | 补齐实际运行时依赖（含 BaoStock）；同步 `version`、锁文件、README、CLI 版本。 |
| P0-06 | 建立发布前检查命令 | P0-01~05 | 一个命令执行格式、lint、类型、测试、包构建和元数据校验，并记录在 README。 |

## P1 — 自动化质量门禁

| ID | 任务 | 依赖 | 完成标准 |
|---|---|---|---|
| P1-01 | 引入 Ruff 与 pre-commit | P0-06 | `ruff check`、`ruff format --check` 可本地与 CI 执行；提交前自动执行基础检查。 |
| P1-02 | 建立类型检查基线 | P0-06 | 选择 pyright 或 mypy；核心包无新增类型错误，公共接口完成注解。 |
| P1-03 | 新建 GitHub Actions CI | P0-06 | Python 3.10/3.11/3.12 矩阵运行安装、lint、类型检查、测试和构建。 |
| P1-04 | 覆盖率与关键路径门槛 | P1-03 | 输出覆盖率报告；风控、订单、数据校验、报告持久化和 Web 核心函数设定门槛。 |
| P1-05 | 依赖与安全扫描 | P1-03 | Dependabot、pip-audit/OSV、CodeQL、secret scan 在 CI 运行；高危结果阻断合并。 |
| P1-06 | 主分支保护规则 | P1-03~05 | 要求 CI 通过、至少一次审查、禁止直接 push。 |

## P2 — 开源协作契约

| ID | 任务 | 依赖 | 完成标准 |
|---|---|---|---|
| P2-01 | 编写贡献指南 | P0-06 | `CONTRIBUTING.md` 覆盖开发环境、分支、测试、提交、PR 与文档贡献流程。 |
| P2-02 | 建立社区与安全政策 | P2-01 | 添加 `CODE_OF_CONDUCT.md`、`SECURITY.md`、`SUPPORT.md`；安全漏洞有私密披露流程与响应预期。 |
| P2-03 | Issue/PR 模板 | P2-01 | 提供 Bug、数据问题、功能建议、文档与 PR 模板，要求复现信息和风险说明。 |
| P2-04 | 版本与发布规则 | P0-05 | 添加 `CHANGELOG.md`、语义化版本策略、弃用政策、release checklist。 |
| P2-05 | 治理与授权 | P2-01 | 明确维护者、决策机制、Review 要求、DCO/CLA 选择和路线图入口。 |

## P3 — 数据与研究可复现

| ID | 任务 | 依赖 | 完成标准 |
|---|---|---|---|
| P3-01 | 定义数据谱系 schema | P0-05 | 为行情、财务、分析报告和回测定义 source、时间、复权、缓存年龄、缺失项和降级原因字段。 |
| P3-02 | 报告展示数据状态 | P3-01 | Markdown/HTML/JSON 都醒目显示数据来源、生成时间、样例/缓存/实时标识和警告。 |
| P3-03 | 分离数据层测试 | P0-03 | fixture 数据、样例数据、缓存数据和联网 smoke 数据目录/标签明确分开。 |
| P3-04 | 回测实验快照 | P3-01 | 每次回测保存策略版本、参数、数据版本、随机种子、Git SHA 和依赖锁文件摘要。 |
| P3-05 | 回测现实约束路线图 | P3-04 | 逐项实现并测试交易日历、停牌、涨跌停、复权、分红、流动性、滑点与偏差控制；未实现项在报告中披露。 |

## P4 — 安全与交易边界

| ID | 任务 | 依赖 | 完成标准 |
|---|---|---|---|
| P4-01 | 明确运行模式 | P2-04 | 文档与 CLI 区分 research/backtest/paper/live；默认不可实盘下单。 |
| P4-02 | 实盘适配器隔离 | P4-01 | 实盘交易为独立可选包/插件；基础安装不包含任何可下单凭据或路径。 |
| P4-03 | 实盘安全控制 | P4-02 | 实现人工确认、金额限制、日限额、幂等 ID、交易时段校验、撤单和 kill switch，并有演练测试。 |
| P4-04 | Web 服务加固 | P0-04 | 默认 loopback 绑定；远程模式要求认证、速率限制、输入限制、路径安全和安全文档。 |
| P4-05 | 密钥与日志脱敏 | P1-05 | 自动扫描密钥；日志、异常、报告和测试 fixture 无敏感信息；脱敏规则有测试。 |

## v1.0 发布任务

| ID | 任务 | 依赖 | 完成标准 |
|---|---|---|---|
| R1 | Release candidate 演练 | P0~P4 | 在全新环境完成安装、离线演示、联网 smoke、回测复现和包安装验证。 |
| R2 | TestPyPI 与构件验证 | R1 | 在 TestPyPI 安装并验证 CLI；发布 sdist/wheel、checksums、release notes。 |
| R3 | 社区首发 | R2 | 发布 v1.0、路线图、good first issues 和 Discussions；定义首个季度维护节奏。 |

## 建议执行顺序（前两周）

1. P0-01、P0-02：恢复绿色测试，并防止相同 mock 契约问题重现。
2. P0-03、P0-04：让开发与 CI 不依赖外网，消除 TLS 风险。
3. P0-05、P0-06：将可安装性和发布检查固化下来。
4. P1-01、P1-03、P1-05：优先让质量门禁在每个 PR 上自动执行。
5. P2-01 至 P2-04：在邀请外部贡献前完成最小协作契约。
